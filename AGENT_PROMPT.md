# ricepilot — implementation brief for an agentic coding system

You are the ORCHESTRATOR for building **ricepilot**, a Rust CLI that switches a Linux desktop between complete "rice" profiles (dotfile sets) by atomically re-pointing directory symlinks, with the single overriding requirement that it must NEVER break the user's system or modify any profile's contents. You plan, delegate to sub-agents, integrate, and gate every milestone with a red-team review. Read this whole brief before doing anything.

## 0. Non-negotiable rules (apply to you and every sub-agent)
R1. Development happens ONLY inside the repo and in throwaway temp directories created by tests under a configurable fixture root. Never read, write, link, move or delete anything under the real `$HOME/.config`, `$HOME/.local`, or the user's caelestia clone until milestone M5's supervised acceptance run, and then only via the tool's own dry-run→`--commit` path with the user present.
R2. The tool's codebase must contain NO delete primitive outside `src/gc/` (`unlink`, `rmdir`, `remove_dir_all`, `remove_file`, `fs::remove_*`, `rm`, `rmtree`). Displaced things are renamed into an attic. A CI grep enforces this; make it fail before you write the first op.
R3. The tool never opens a profile file for writing, never templates or `sed`s, never writes through a symlink, never runs `git stash/checkout/clean/reset` on a user repo, never runs `sudo`, never writes under `/etc`, never invokes `caelestia install|update`, `install.fish` or any rice installer.
R4. Every mutating command is dry-run by default and requires `--commit`. Every mutation is preceded by a complete two-phase pre-flight and a fsync'd write-ahead journal. Refusals name the path and the rule, exit non-zero, and have zero side effects.
R5. "Not possible" is a valid, first-class outcome. When a layer cannot be switched safely, the tool declines and explains; it never half-applies.
R6. Ask the user (do not guess) whenever a decision changes what gets touched on the real machine. Decide routine engineering questions yourself and record them in `docs/DECISIONS.md`.
R7. Report truthfully: failing tests are reported as failing; skipped steps as skipped.

## 1. Target machine facts (verified; design against these, re-verify only read-only)
- CachyOS/Arch, Hyprland 0.55.4 started by uwsm 0.26.5 under SDDM autologin (`Session=hyprland-uwsm.desktop`, `Relogin=false` → session exit reaches the greeter; greeter's plain `Hyprland` entry is immune to anything in `$HOME`; `start-hyprland` relaunches with `--safe-mode` after a crash; TTYs F2–F6 exist). Rust 1.96 (distro, glibc-only, no rustup), paru.
- btrfs: `/` (`@`), `/home` (`@home`), `/tmp` (tmpfs), `/var/tmp` (`@tmp`) all have DIFFERENT `st_dev` → `rename(2)` across them fails with `EXDEV`. Everything the tool renames must live under `/home`. snapper has only a `root` config; rootless btrfs snapshots are unavailable (EPERM).
- The user's rice is **caelestia** (`~/.local/share/caelestia`, git clone with 9 modified + ~20 untracked files = their stable state; never touch the worktree). It is already a symlink farm: 7 DIRECTORY links in `~/.config` (`hypr fish foot btop fastfetch uwsm spicetify`) and 2 FILE links (`starship.toml`, `codium-flags.conf`). Documented VSCodium file links do not exist (installer raced) — never trust a documented layout, always `lstat` reality.
- Hazards on the machine: caelestia's `install.fish` does `rm -rf` on overwrite; `caelestia-cli` `install/update` uses `rmtree` and can delete `~/.local/share/caelestia` via its legacy-migration path; caelestia's theme engine (`caelestia shell -d`) rewrites ~20 files per scheme change with tempfile+`os.replace` (destroys symlinks at those paths): in-tree `hypr/scheme/current.conf`, `btop/themes/*`, `spicetify/…/color.ini`; out-of-tree `~/.config/{fuzzel/fuzzel.ini, cava/config, htop/htoprc, gtk-3.0/*.css, gtk-4.0/*.css, nvtop/nvtop.colors, qtengine/*, zed/themes/caelestia.json, <discord clients>/themes/*}` — these are GENERATED, never profile content. Other in-tree runtime writers: `hyprland.conf`'s `exec = cp … scheme/current.conf` (re-runs on every `hyprctl reload`), `hypr/scripts/configs.fish` (touches `~/.config/caelestia/hypr-{vars,user}.conf`), fish `fish_variables`, btop on exit, `shell.json` continuously, and the user's `~/.local/bin/hypr-session` (`mkdir -p ~/.config/hypr/sessions` on every call).
- Real user-owned dirs that are also rice: `~/.config/caelestia` (path hardcoded by caelestia-cli), `~/.config/quickshell/{overview,sgtest}`, `kitty`, `ghostty`, `nvim`, `tmux`, `waypaper`, `swappy`, `~/.zshrc`, `~/.bashrc`. `~/.config` is 7.9 GB / 128 entries; ~20 are rice → allowlist-only.
- Hyprland: holds no open fd on config files (retargeting `~/.config/hypr` is harmless until reload); `hyprctl reload` does NOT reset the runtime submap (all user binds live in submap `global`) → any live reload must be followed by `hyprctl dispatch submap reset` and a bind-reachability probe; `Hyprland --verify-config -c <file>` returns 0/1 but parses twice and FORKS every `exec =` line on the second pass → only run it on a scratch copy with `exec =`/`execr =` lines stripped, absolute path variables rewritten to the scratch copy, and `HYPRLAND_INSTANCE_SIGNATURE` unset; treat exit 0 as "syntax OK" only. `hyprctl config full-reload` does not exist. Hyprland ≥0.55 may use `hyprland.lua`; be dialect-agnostic.
- Login-only: `~/.config/uwsm/env-hyprland` (env), `exec-once` daemons, dconf/`DCONF_PROFILE`, `QTENGINE_CONFIG`, systemd user units. Clean logout = `uwsm stop` (never `hyprctl dispatch exit`, never kill Hyprland).

## 2. Product decisions already made (do not re-open)
- Name: `ricepilot`. Language: Rust, `#![forbid(unsafe_code)]`, `rustix` as the only syscall layer, no `nix`, no async, no musl, no `panic=abort`, dynamic glibc, `lto="thin"`, `codegen-units=1`, `strip="symbols"`, committed `Cargo.lock`, `PKGBUILD`.
- `switch` = atomic on-disk relink only, effective at next login; optional `--relogin` runs `uwsm stop` after a y/N. Live apply is NOT in v1.
- Packages: profiles declare `requires = [...]`; the tool checks with `pacman -Q` and prints the exact `paru -S --needed …`; it never installs or removes.
- v1 activation kind is `dir-link` only. `file-copy` (copy-deploy with ledger + 3-state divergence check) is v1.1. `generated` and `volatile` are classification kinds, never activated.
- `~/.config/uwsm`, `~/.config/systemd`, `environment.d`, `autostart`, `dconf`, `pulse`, `mimeapps.list`, `user-dirs.*`, browsers/Electron dirs, `~/.ssh`, `~/.gnupg`, keyrings, editor `settings.json` are hard-denylisted in v1.

## 3. Architecture to implement (see docs/DESIGN.md you will write first)
Data: `~/.local/share/ricepilot/profiles/<name>/{profile.toml, payload…}` (a profile may instead set `root = <external dir>` = by-reference, e.g. the live caelestia clone); `~/.local/state/ricepilot/{ledger.toml, generations/NNNN.toml + current, journal/, attic/<ts>/, baseline/, rescue.sh}`; lock at `$XDG_RUNTIME_DIR/ricepilot.lock` via `flock(LOCK_EX|LOCK_NB)` held for the process lifetime.
Manifest `profile.toml`: `name`, optional `root`, `requires`, `hypr_dialect`, `[[path]] {dest, src, kind = dir-link|file-copy|generated|volatile, activation = relogin|live|never}`, `volatile` globs (seed from the profile's `.gitignore` ∪ discovered writers; excluded from hashing; report-and-proceed unless `--strict`), `generated` list (backed up to attic on switch, never linked).
Ownership of a live path = ALL of: `O_PATH|O_NOFOLLOW` open is `S_IFLNK`; `readlinkat` target lexically inside a registered profile root; ledger entry matches path, target and `(dev, ino)`. Otherwise the path is unowned → refuse.
Modules: `observe.rs` (five shapes: owned link / foreign link / real dir / real file / absent; dirfd + `*at()` only; `st_dev`, `statfs` f_type), `plan.rs` (PURE: `(Observed, Target) -> Plan`, zero IO), `ops/` (the only mutators: `create_symlink_tmp`, `exchange` = `renameat2(RENAME_EXCHANGE)` probed once with fallback rename-to-attic-then-rename, `rename_to_attic`, `fsync_dir`, `acquire_lock`, `write_atomic` = temp+fsync+rename+dir fsync; enforced by clippy `disallowed_methods` and a CI grep for `std::fs`/`rustix::fs` outside `src/ops/`), `journal.rs` (WAL; state-driven idempotent replay), `ledger.rs`, `manifest.rs`, `generations.rs`, `rescue.rs` (regenerates a fully unrolled POSIX sh script with absolute binary paths, `ln -sT tmp && mv -T`, `sh -n` checked, written atomically, as a real file), `doctor.rs`, `verify.rs` (blake3 manifest: content hash for files, target-string hash for symlinks, mode/uid/gid/mtime_ns/type recorded), `gc/` (only place with unlink/rmdir; itemises; requires typing the attic dir name), `cli/`.
Switch algorithm: A) lock → observe → classify → plan → pre-flight refusals (unowned, `st_dev` mismatch, denylist, nested/mountpoint, missing requires, sandboxed verify-config) → print plan → stop unless `--commit` → create temp links → write+fsync journal (file AND directory). B) tight loop of `exchange` calls only. C) attic moves, dir fsyncs, generation NNNN + `current` flip, POST record, regenerate `rescue.sh`, print the relogin notice with exact commands. `rollback` re-applies generation NNNN-1 through the same path; `recover` replays the journal by observing reality; `rescue` is TTY-safe (no D-Bus/hyprctl/fish/quickshell).
Commands v1: `init`, `status`, `doctor`, `list`, `show`, `capture`, `adopt`, `plan`, `switch [--commit] [--relogin] [--strict]`, `rollback`, `recover`, `rescue`, `verify`, `diff`, `gc`.
`init` registers the live caelestia rice BY REFERENCE (root = the clone), adopts the 7 existing dir-links only after explicit per-path confirmation, and takes a `cp -a --reflink=auto` baseline copy into `state/baseline/` (copy, never move; preserve 600 modes, symlinks as symlinks, times; report absolute symlinks inside the tree, e.g. `userChrome.css → /home/…/caelestia/zen/userChrome.css`; propose mode-600 files as volatile for confirmation).
`adopt <path> --into <profile>` converts a real user dir into a profile-owned dir-link: copy into the profile, verify hashes, then `exchange` the real dir with the link (displaced dir → attic). Per path, confirmed, journalled. It is the riskiest command; treat it accordingly.
`doctor` reports: are owned links still links (caelestia-cli's installer converts them back to real dirs); caelestia-cli legacy-migration hazard; `hypr-session` writes into the profile tree (propose a one-line `SESSION_DIR` patch, never apply it); foreign theme daemons running (`caelestia shell -d`, `caelestia resizer -d`); `/home` unsnapshotted (print the root-only `snapper -c home create-config /home` command, never run it); any relogin-scoped drift since the last switch.

## 4. Milestones and gates
M0 Scaffold: repo, `Cargo.toml`, CI (fmt, clippy `-D warnings`, forbid-delete grep, ops-boundary grep, tests), `docs/DESIGN.md`, `docs/SAFETY.md` (invariants R1–R7 + section 3), `docs/NOT-POSSIBLE.md`, `docs/DECISIONS.md`. Gate: CI red on a deliberately planted `remove_dir_all`.
M1 Observe + Manifest + Plan + `plan`/`status`/`list`/`show` (dry-run only). Gate: proptest `plan(s, s)` is empty; five-shape fixtures; `insta` snapshots of plan output and every refusal message.
M2 Ops + Journal + Attic + `recover`. Gate: real-temp-dir tests with a configurable fixture root (default a dir under the repo's `target/`, NOT `/tmp`); `RENAME_EXCHANGE` probe and fallback both tested; crash injection (abort after step k, then `recover`) ⇒ fully old or fully new, never mixed; apply-then-rollback restores byte-exact link topology and leaves every pre-existing target's inode/mtime unchanged.
M3 Generations + `rollback` + `rescue.sh` + ledger + `verify`. Gate: `rescue.sh` executed by `/bin/sh` in a fixture restores the previous generation; `verify` ignores volatile paths and flags a one-byte change elsewhere.
M4 `capture`, `adopt`, `init` (by-reference + baseline). Gate: capture preserves 600 modes and symlinks; absolute in-tree symlinks reported; `adopt` on a fixture with a real dir + a foreign symlink + a dangling link behaves per the five-shape table; nothing is ever deleted (attic contains the displaced dir).
M5 `doctor`, requires-check, sandboxed verify-config, `--relogin`, `diff`, `gc`, README + `docs/RECOVERY.md` (TTY steps, `Hyprland --safe-mode`, greeter fallback) + `PKGBUILD`. Gate: red-team review passes; then the SUPERVISED acceptance run with the user: `doctor` → `init` (dry) → `init --commit` → create a minimal `bare` profile → `switch bare` (dry) → `--commit` → `uwsm stop` → login → `rollback --commit` → login → `verify caelestia` clean, `git -C ~/.local/share/caelestia status` unchanged, all 7 links intact.
Later (do not build now): v1.1 `file-copy`; v2 confirm-or-revert self-heal hook in `~/.config/uwsm/env-hyprland.d/` (POSIX sh, `|| true` on every line, no `exit`), per-profile `~/.local/state/caelestia`, `DCONF_PROFILE`/`QTENGINE_CONFIG` env generation, opt-in `--live` for the quickshell layer with dead-man auto-rollback; v3 `try` clean-room mode via `XDG_CONFIG_HOME` from a TTY, fuzzel picker.

## 5. Sub-agent plan (spawn these; give each this brief plus its section; run reviewers in parallel with builders where possible)
- **architect** (first, alone): writes `docs/DESIGN.md`, `docs/SAFETY.md`, `docs/NOT-POSSIBLE.md`, the manifest schema, the five-shape × action decision table, the `Plan` and `Op` types, and the CLI surface. Output is reviewed by **red-team** before any code.
- **ops-engineer**: `src/ops/`, `journal.rs`, lock, `RENAME_EXCHANGE` probe/fallback, fsync discipline, atomic writes. Owns the CI boundary greps. Must not touch `plan.rs`.
- **core-engineer**: `observe.rs`, `manifest.rs`, `plan.rs` (pure), `generations.rs`, `ledger.rs`, `verify.rs`, `rescue.rs`.
- **cli-engineer**: `clap` surface, dry-run default, `--commit`, output wording (every message snapshot-tested), `inquire` confirmations, `doctor`, `--relogin` via `uwsm stop`.
- **test-engineer**: fixture harness on real temp dirs with configurable root, proptests, crash-injection harness (kill after step k), `rescue.sh` execution test, snapshot tests; keeps coverage of every refusal path.
- **red-team** (adversarial; runs at every gate; at least two independent instances at M2 and M5): tries to make the tool delete, overwrite, half-apply, follow a symlink it should not, cross a filesystem, act on an unowned path, mis-classify a generated file as profile content, or leave the machine unbootable; also audits that no delete primitive exists outside `gc/`. Any finding blocks the gate.
- **docs-writer** (M5): README, RECOVERY, PKGBUILD, honest limits ("GTK colours follow only apps started after login", "the tool never writes into a profile, but apps do — see volatile").
Orchestrator duties: keep `docs/DECISIONS.md` current, integrate branches, run the full CI locally before each gate, summarise each gate's red-team findings and fixes to the user, and stop to ask the user before M5's acceptance run.

## 6. Definition of done (v1)
All gates green; CI proves no delete primitive outside `gc/` and no fs mutation outside `src/ops/`; every mutating command is dry-run by default; `rescue.sh` works from `/bin/sh`; the supervised acceptance run completed with the caelestia worktree byte-identical (`git status` unchanged, `verify` clean) and all original links intact; `docs/NOT-POSSIBLE.md` lists every declined capability with the reason.
